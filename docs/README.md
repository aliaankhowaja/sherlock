# Docs

Our own notes were once treated as truth by agents. Every document now has an authority tier.

| Tier | What | Examples |
|---|---|---|
| 0 Official | University documents | FYP guide, rubrics, supervisor instructions |
| 1 Submitted | What we handed in | proposal, mid report |
| 2 Evidence | What can be re-run or re-read | the code, test output, `docs/eval/results.json` |
| 3 Working notes | Everything we or agents wrote | status, specs, plans, logs, this folder's `notes/` and `history/` |

**Rule:** tier 3 is orientation only. It can be stale and is never cited as truth. If a note disagrees with tiers 0-2, the note is wrong.

**One-way rule:** a build spec (tier 3) may cite the mid report's requirement IDs. The report never cites notes.
